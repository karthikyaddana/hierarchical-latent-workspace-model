**Program status.** The v5–v9 program closed at v9.0 rung 1 (terminal for the
workspace generative mechanism under that preregistration;
`reports/hlwm-v9.0-session-h-results-2026-09-03.md`). v10 is a NEW program,

deterministic label routing where collapse is impossible by construction.
Lanes: cut as a claim (nine cosine-collapse failures + zero positive ≤1B

Research basis: 12-lens arXiv sweep + 3 component syntheses + merged recipe +
adversarial critique, 2026-09-03 (raw:
`reports/hlwm-v10-research-raw-2026-09-03.json`). Core evidence: CODI
(arXiv:2502.21074 — LoRA-only latent CoT at 124M/1B, w/o-L1 ablation 43.7→24.5

1B + LoRA + latent head, dense per-position CE is load-bearing), SIM-CoT
(2509.20317 — per-latent step supervision stops latent homogenization),

**Honest headline gap (preregistered):** every published latent-channel

  length-normalized logprob, token entropy, **discrete semantic entropy over
  the N=8 pool (mandatory)**, P(True), verifier-head-alone; max-logprob is

- **Control (finally):** plain-LoRA SFT control — see §6 branch logic.

## 2. Channel design

- **K = 6 latent thoughts** (CODI's peak; 42 was the unsupported collapse
  regime). Autoregressive continuous thoughts: last hidden → 2-layer
  MLP+LayerNorm projection → next input embedding, latents normalized to the
  base embedding std (CoLaR grounding — latents live inside the embedding
  distribution by construction).
- **Interface: per-layer KV prefix.** Sidecar trunk → per-layer low-rank
  heads → m=16 KV slots per layer, Qwen3-0.6B GQA layout (8 KV heads ×
  head_dim 128), all 28 layers. Slots append to K/V directly — they never
  pass through RMSNorm as tokens, killing that inertness class structurally.
- **Gate (critic-corrected):** post-softmax mixing ratio per layer-head:
  softmax prefix scores separately from word scores, prefix branch ×
  tanh(g), **init g such that tanh(g) = 0.08** (NOT zero-init: at g=0 the
  prefix-projector gradient is exactly zero — the v8 frozen-α failure).
  **Blocking step-0 unit tests: (i) ‖∂L/∂g‖ > 0, (ii) ‖∂L/∂(prefix-projector
  params)‖ > 0, (iii) perturbing g changes output logits measurably.** A
  test that only checks (i) certifies a broken instrument (v8 leak-gate
  class) and is insufficient by prereg.
- **Warm phase (steps 0–600): reconstruction pretraining.** Decoder
  conditioned on latents + `[RECON]` cue reconstructs premise + trace, CE
  weight 1.0. **Kill gate (critic-corrected, trajectory-based):** calibrate
  on the first 200 warm steps; prereg = held-out digit-level EM slope
  positive over steps 200–600 AND level within the band derived from the
  smoke extrapolation (recorded in the run log before step 600). A fixed
  0.98 threshold is explicitly NOT used (merge artifact; ~9× compression at
  0.6B/600 steps has no evidence). Failing the gate → abort branch (§6).
- **Main phase loss** (single stage, no optimizer resets, shared LoRA):
  `L = 1.0·CE_teacher(Q + gold trace + A; final answer-step excluded)
     + 1.0·CE_student(A | Q, 6 latents)
     + γ·smoothL1(student vs teacher hiddens at the pre-answer token, all
        layers, per-layer EMA-std normalization, stop-grad teacher)
     + 0.5·CE_CoLaR (latents teacher-forced as compressed gold-trace
        embeddings, per-position CE, fully parallel)
     + 0.3·CE_recon (continued premise reconstruction)`
  γ calibrated in smoke over {5, 10, 20}. Free-running student decode on
  ≤25% of steps. **KL-to-base and all KL anchors DELETED entirely**
  (critic: the "optional" self-with-premise anchor shipped in v9 and the
  channel still read 0.000; no positive in-house evidence — removed).
- **Gradient-conflict telemetry (critic addition):** per-term grad norms +
  pairwise grad cosines logged every 100 steps; preregistered interference
  diagnostic (persistent cosine < −0.5 between any pair = flagged in
  verdict); PCGrad (arXiv:2001.06782) is the named optimizer fallback if
  smoke shows conflict.
- **Optimizer:** LoRA r64 all layers (r128 = fallback if smoke shows T4
  memory headroom), lr 8e-4 cosine + 3% warmup, AdamW wd 0.1, bf16.
- **Token-id hygiene:** every anchor/L1 target id verified real (never
  bos/eos — the v8 root cause), asserted in unit tests.

## 3. Experts design

- N=2 routed r16 LoRA experts on decoder MLP projections only
  ({numeric, unit}→E1; {ordering, abstention}→E2), + always-on shared
  backbone r64 LoRA (DeepSeekMoE isolation; "absorbs common content" is a
  mechanism hypothesis, not a claim). Sequence-level deterministic routing
  from gold family labels. **Balance = the dataloader** (stratified so each
  grad-accum-16 window is family-balanced); NO balance loss (per-microbatch
  LBL erases specialization, arXiv:2501.11873). Collapse impossible by
  construction.
- Router = detached linear probe on mean-pooled prompt hidden state, CE
  weight 0.1, small-normal init (no zero-init on the router path). StableMoE
  Stage-2 frozen-argmax switch at step 1,800 ONLY if held-out router
  accuracy ≥ 0.95 on paraphrase-shifted rows; else label-routed all run
  (reported, not failed).
- **Load-bearing audit arms (never cut):** (a) cross-routing ablation —
  family-A rows through E2 must cost ≥ 0.05; else the section re-scopes to
  negative evidence; (b) label-routed vs router-routed delta ≤ 0.02;
  (c) matched-capacity r32 dense MLP-LoRA control (same trainable params as
  the routed pair).
- Disclosed weakness: ~4.4k presentations per routed expert is genuine
  starvation; the shared expert is the mitigation.

## 5. Data spec (generator)

Per row: gold compact trace, equation-only GSM8k-Aug format
(`<<a op b = c>>`), ≤3 steps, ≤30 trace tokens, NL stripped; final
answer-producing step excluded from teacher CE; indexed per-step value
literals (SIM-CoT decode targets); premise literals + masked-prompt variant

stratum preserved. Emit 25k rows (single epoch consumes ~8.8k presentations;
audit/calibration/banding pools draw from the remainder).

### A1. Training-side information asymmetry (fatal fix — the load-bearing one)
In ≤3-step synthetic families the teacher's pre-answer hidden is a function of
Q alone, so the L1 and CE_student exert ZERO pressure to route information
through the latents if training prompts are unmasked. Therefore: the student
channel (CE_student and the L1 anchor row) reads the MASKED premise on ≥50%
of main-phase rows (v9's alternating-masked-batch pattern); latents are
produced from the full premise. Train-time masked numeric EM is logged every
100 steps and feeds the go/no-go (A3). This marries v9's necessity to v10's
density — density without asymmetry re-derives the v9 null.

### A2. Producer supervision + anti-homogenization (per-latent losses)
CE_CoLaR as drafted supervises only the consumer. Add: (a) per-latent
producer loss MSE(self-generated latent_i, stop-grad compressed-gold
embedding_i); (b) SIM-CoT per-latent decode CE on SELF-generated latents
(targets already in the data spec) — this same term is the
anti-fixed-point-attractor mechanism (the 6 AR latents otherwise recreate the
lanes collapse inside the channel). Teacher-forcing of latent inputs anneals
to ≤25% by step 1,000. Telemetry every 100 steps: pairwise inter-latent
cosine (diagnostic: mean < 0.90 by step 1,200), cosine(self-latents,
gold-compressed), teacher-forced vs free-running CE_student gap.

### A3. Gates rewritten for decidability
- **Warm kill gate (replaces §2's trajectory band):** absolute held-out
  digit-level reconstruction EM ≥ 0.50 at step 600, fixed now, before any
  run; AND EM@600 ≥ 2× EM@200. Trajectory band demoted to telemetry.
- **Step-1,200 go/no-go (replaces "masked acc > 0", which a dead channel
  passes at ~0.17 via abstention/ordering guess floors):** masked
  NUMERIC-family exact-match ≥ 0.05, abstention and ordering rows excluded;
  per-family masked acc reported as telemetry.
- **Channel margin gates:** arms are paired on identical rows; each gate =
  one-sided 90% lower confidence bound of the paired delta > 0, with the
  point margins (§4) reported descriptively. The 0.05/0.10 two-tier
  distinction is deleted (indistinguishable at our n). Disclosed MDE at the
  160-row masked core: a true delta ≈ 0.13–0.15 is needed for reliable
  both-seed passage.
- **probe_generation_gap:** evaluated ONLY if latent_channel_live passes;
  probe = linear, premise-digit target, trained on 512 held-out latents,
  with liveness precondition probe ≥ chance + 0.10.
- **Gate liveness in-run (v8's frozen-α class, step-0 tests can't see it):**
  gate scalars EXEMPT from weight decay; per-layer tanh(g) and prefix
  attention-mass telemetry every 100 steps; liveness floors at steps 600 and
  1,200 (median prefix attention mass ≥ 0.02 on layers 8–28) folded into the
  go/no-go.
- **Expert liveness precondition:** per-expert relative output norm
  ‖B_iA_ix‖/‖shared-path‖ logged; the cross-routing null is interpretable as
  negative evidence ONLY if expert norm ≥ 0.10 relative; below floor →
  "experts never engaged" (infrastructure finding, not science).
- **w/o-L1 ablation DEMOTED from Claim B conjunct to supporting diagnostic**
  (a 300-step γ=0 continuation from a converged checkpoint cannot unlearn;
  the CODI 43.7→24.5 evidence is from-scratch). Claim B rests on the paired
  margin gates alone. The w/o-L1 branch trains from the WARM checkpoint for
  the branch budget and is reported descriptively.

**A. "Verbalizable Representations Form a Global Workspace in Language
Models" (arXiv:2607.15495).** The J-lens identifies, per layer, the
corpus-averaged linearized effect of activations on the future likelihood of
verbalizing each token; the spanned J-space functions as a global workspace
(reportable, summonable, used for silent reasoning), is coherent only in an
INTERMEDIATE band of layers, and holds tens of concepts. Mapping to this
program: the v9 terminal signature — probe 0.30, generation 0.000 — is
exactly "content present in activations but OUTSIDE the verbalizable
subspace." v10's per-latent decode CE (through the frozen lm_head) is
already, in this frame, direct pressure pushing latent states INTO J-space;
CoLaR grounding puts them at the right scale.
- **Preregistered prediction P-J1 (costs nothing; telemetry already
  collects it):** the per-layer prefix attention gates open predominantly in
  the intermediate layer band and stay near init at the earliest and final
  layers. Confirmation strengthens the J-space reading; violation is
  reported, not gated.
- **Preregistered contingency v10.1-J (only if rung 2 recurs with the
  probe-positive/generation-zero shape):** restrict or bias KV-slot
  injection to the intermediate band, and project slot values into an
  approximate J-space computed once for the pinned base (corpus-averaged
  Jacobian readout for the ~200 task-relevant tokens: digits, operators,
  units). Writing where the decoder verbalizes, by construction.

**B. "Language Models Can Control Their Own Attention" (arXiv:2609.02737,
Declarative Attention).** Zero-shot protocol on 27-31B instruct models:
the model declares <global>/<focus:segment>/<local> in its own output, and
the engine enforces the declaration as a segment-level attention mask
(31-52% attended-token reduction, 1.3-2.75pp accuracy cost, gap shrinks
with scale). Not aimed at our failure (inference efficiency at long
context), and a 0.6B base cannot follow the protocol zero-shot — but it is
the strongest published template for the TEXTUAL-workspace fallback:
- **Named fallback HLWM-2-DA (post-v10, if latent channels remain dead at

Three defects, all in bundle code, none in the model:

1. **Warm-gate predicate structurally unsatisfiable in the good regime.**

   clause applies only when `em_200 < floor`. This is the same broken-
   instrument class as the v8 RMSNorm-invariant gate alpha; the in-run
   tripwire joins the M4-style liveness rule: a gate must be satisfiable in
   the regime it certifies.
2. **Abort paths wrote no `v10_verdict` record to metrics.jsonl.** The
   notebook reads the abort status from metrics.jsonl; both early returns
   (warm gate, go/no-go) now append the verdict record before returning
   (regression test reads metrics.jsonl in the tiny end-to-end abort run).
   Without it, session I-4's notebook treated the warm-abort checkpoint as

3. **Audit population never filtered to the preregistered families.** The
   master test split carries 585 pre-v10 corpus rows (426 untyped, 68

   four anchor families; this makes the code match the prereg.

## 15. Pre-launch verification amendments (BINDING — appended 2026-09-05)

A four-lane adversarial workflow (18 agents) audited the I-5 fixes before
launch instead of after. It found that the two most consequential §14
conclusions were **wrong**, and that the relaunch as scoped in §14 item 3
would have consumed a session.

### 15.1 The session I-5 go/no-go abort was an INSTRUMENT abort

`v10_masked_numeric_em` selected rows with
`row["evaluation"]["masked"]`, a key `normalize_episode` does not emit —
the flag is top level. `picked` was therefore always empty, the function
returned its `0.0` no-rows default, and both seeds aborted at step 1,200
**without a single row ever being decoded**. A perfectly working channel
would have produced the identical verdict.

§14's "a REAL preregistered abort, not an instrument abort" is retracted.
The masked-transfer claim is **untested**, not falsified, and the relaunch
must allow the tripwire to genuinely pass (resume trains steps 1,200-2,000,
~1.5-4h, rather than re-aborting in fifteen minutes).

The same nested read in `v10_anchor_indices` silently disabled the
Amendment A1 masked-oversampling floor for the whole of I-5: the sampled
masked share was 0.370/0.375 against the preregistered ≥ 0.50. Both are
fixed; both now have regression tests that run against **normalized** rows,
which is the only schema these selectors ever see in production.

Structural fixes so this class cannot recur:

1. An empty tripwire population now **raises** instead of returning 0.0.
   An empty selector is an instrument fault, never evidence.
2. The blocking preflight gained `tripwire_population_live` as a REQUIRED
   check: it certifies the masked anchor buckets (train and validation) and
   the go/no-go's own row selection are non-empty *before* any GPU-hour
   commitment. Tripwire selectors, not just thresholds, are now audited
   instruments.

### 15.2 The notebook could have run stale code (launch-blocking)

Cell 3 took `archives[0]` / `manifests[0]` from an unsorted glob. Kaggle
auto-extracts uploaded zips, so the manifest-name fallback runs; and the
resume attachment (§14 item 3) is a kernel output containing a **complete
old copy of the code tree** with an identical manifest name, version, counts
and self-consistent shas. Selection was a coin flip, and losing it meant
running pre-fix code for a full session — including the resume guard, so
training would have continued 800 steps past a binding abort and then
crashed at the same dtype defect 5-7h in.

Cell 3 now selects **by content**: the notebook pins the sha256 of the
manifest's `code_sha256` map (injected at build time, deterministic, no
timestamps so the zip stays reproducible), prints every attached candidate
with MATCH/stale, and **fails closed** if none matches. Any number of stale
trees may be attached for resume. The builder refuses to write an unpinned
notebook, and `scripts/test_hlwm_v100_notebook.py` tests the invariant.

Consequence for launch: the notebook is no longer stable across rebuilds.
**Both files must be uploaded together from now on.**

### 15.3 Audit scheduling (wall-clock and blast radius)

The audit ran both seeds sequentially on `cuda:0` with GPU1 idle, putting
the session at ~9.5-11.6h against the 12h cap; and an exception while
auditing seed 17 destroyed seed 29's audit too — which is exactly what
happened in I-4 and again in I-5.

`evaluate_v10.py` gained a `--output-dir/--data-dir/--seed` CLI
(`run_seed_audit`, entry point last statement, `--help` covered by test).
Cell 9 launches one audit subprocess per GPU, waits, and reports per seed;
a failed seed prints its log tail and the other still lands. Cell 11 no
longer deletes every `checkpoint-step-*.pt` when there is no full
checkpoint — on an abort branch it promotes the newest step to the
resumable, so the salvage deliverable stops shipping zero weights.

### 15.4 New instrument: gold-answer teacher-forced CE

Ten studies scored what the channel **emits**; nothing scored what it
assigns to the **right answer**, so a null emission result could not
distinguish an exposure gap from a content gap. `gold_forced_ce_block`
scores the gold `public_target` under teacher forcing in four arms on a
bounded, deterministic, family/masked-stratified sample (default 128 rows,
four forwards each — cheap against the 8-candidate pool on every audit row):

| arm | decoder context | generation path |
|---|---|---|
| `channel_masked` | premise removed | V10 channel (the shipped condition) |
| `channel_full` | premise present | V10 channel |
| `causal_masked` | premise removed | plain channel |
| `causal_full` | premise present | plain channel (substrate ceiling) |

Reported deltas: `exposure_gap = channel_masked − channel_full` (cost of
removing the premise, channel fixed) and `channel_cost = channel_full −
causal_full` (cost of routing through the channel, exposure fixed). On
unmasked rows `exposure_gap` is exactly 0 by construction, which makes the
arm self-checking. This is descriptive telemetry: it enters no gate and no
rung, and it is the number that converts the v10.1 branch decision from
inference to measurement.

### 15.5 Also fixed

- `binding_rung` rungs 3/4 now additionally require `training_complete`.
  Channel gates are computed on the abort checkpoint for the failure
  branch, so a truncated run could otherwise be reported as an established
  claim.
- The 50-step telemetry block stamps `family_index` and `masked_row`. The
  §14 "colar_answer_ce alternating ~0.0005 / ~1.0" diagnostic was
  **telemetry aliasing**: the 50-step log cadence is ≡ 2 (mod 4) against a
  period-4 family rotation, so every logged main-phase row was abstention
  (the lows) or ordering (the highs). Zero numeric or unit observations
  exist anywhere in the I-5 run. Do not read that alternation as a
  masked/unmasked split; it was never one.

### 15.6 The Amendment A1 floor was inert too, and what that means for the relaunch

The same normalized-schema defect that silenced the go/no-go also lived in
`v10_anchor_indices`, which built its `family|m` / `family|u` buckets from
`row["evaluation"]["masked"]`. `normalize_episode` never emits that key, so
every anchor row landed in a `|u` bucket. Measured on the real shipped
`train.jsonl`:

| Bucketing | Buckets built | Masked share the model actually saw (seed 17 / 29) |
| --- | --- | --- |
| Session I-5, as shipped | `abstention\|u` 1024, `numeric\|u` 1024, `ordering\|u` 1024, `unit\|u` 1024 | 0.380 / 0.372 |
| After the fix | + `numeric\|m` 479, `ordering\|m` 510, `unit\|m` 526 | 0.508 / 0.498 |

The failure is *inertness*, not starvation: masked rows were still drawn,
because they were sitting in the `|u` pools and were sampled at their
natural corpus rate. What never happened is the Amendment A1 oversampling
that was supposed to lift that rate to the preregistered floor of 0.50. The
`maskable` list was empty, so `masked_probability` was 0.0 and the
correction term `masked_floor * len(families) / len(maskable)` never ran.
The restored value 0.667 (four families, three maskable) is what produces
the ~0.50 overall share above; `masked_fraction_seen` remains report-only
telemetry and is not a gate, so seed 29's 0.498 is draw noise, not a miss.

**Relaunch decision: fresh run, not a resume.** The step-1200 checkpoint
from session I-5 exists and is resumable, but it was trained under a
violated preregistration — 0.37 masked exposure against a floor of 0.50 —
and it was stopped by an instrument that never decoded a row. Resuming it
would carry an off-spec optimization history into a run whose entire claim
is about masked transfer, and no downstream number could be reported
without that caveat attached. At the measured 6.75 s/step the full 2,000
steps cost about 4.3 h per seed in parallel, plus roughly 3 h of per-GPU
parallel audit: about 8 h against a 30 h quota. The science is worth more
than the 2 h saved. Operationally this requires no flag — cell 8's resume
glob finds nothing when only the fresh bundle is attached, so a clean
upload *is* the fresh run.

### 15.7 Two more instrument defects found while certifying the fixes

**The go/no-go could be passed by copying.** Its grader is substring
containment (`str(expected) in text`), and a sweep of all 2,212 masked rows
across the three splits found five whose answer already occurs inside their
own masked prompt — nested in a distractor, e.g. expected `546` inside the
reference value `69546`. One of those five sat inside the 32-row go/no-go
sample. With the threshold at 0.05 (2 of 32) a single copied answer would
have supplied half the evidence needed to clear a binding tripwire.
`v10_masked_numeric_indices` now excludes any row whose expected answer
appears in its masked prompt; the population is unchanged at 32 (and 64 for
the preflight), so the exclusion is free. The same sweep confirms the real
guarantee holds everywhere: **zero** withheld literals leak into any masked
prompt in any split.

**The test suite preferred the archived Version 6.0 tree.** Both v10 test
modules opened with `try: from experiments.kaggle_hlwm...  except
ImportError: from modeling_hlwm...`. `experiments/kaggle_hlwm` is the
pre-hotfix Version 6.0 tree that Section 7 of the Version 8.0 record
explicitly demotes; the branch is unreachable only while the repo root is
off `sys.path`, and `test_data_v10._builder_module()` puts it there. So
collection order decided which copy of the code got tested: the shipped
notebook and builder pass an explicit file list and were always safe, but a
bare `pytest` in the bundle directory tested the Version 6.0 tree and
reported 43 failures. Both modules now pin their own directory at
`sys.path[0]` and import locally, with no fallback. The suite is 148 green
in all three invocation shapes (bare, builder order, from the repo root);
it was 148 collected / 105 passed in the bare shape before.

This is the same failure class as the notebook's stale-tree coin flip in
Section 15.2, found in a second place: *the wrong copy of the code silently
wins*. Worth stating as a standing rule — every entry point into this
codebase must select its tree explicitly, never by import fallback or list
index.

### 15.8 A certification test that was itself uncertified (found by launching)

The first launch of the certified bundle (kernel version 1, zip
`93602287…`, dataset `hlwm-v10-0-v1-6-certified`) errored 96 seconds in.
The in-session suite reported `1 failed, 147 passed`, and the one failure
was the test added in Section 15.7 to cover the per-GPU audit entry point:
`test_run_seed_audit_plumbing_on_the_session_i5_output_shape`.

`run_seed_audit` defaults its `device` argument to `cuda:0` whenever a GPU
is present and threads that device into `v10_audit`, which places input
tensors on it. The test stubs `load_hlwm` to return a CPU-resident tiny
model, so on any GPU host the two disagree:

    RuntimeError: Expected all tensors to be on the same device, but got
    index is on cuda:0, different from other tensors on cpu

The test passed on the development Mac, which has no CUDA, and could only
fail on exactly the hardware the bundle is built for. The fix pins
`device=torch.device("cpu")` in the call and asserts the stubbed loader
actually received it, so pinning cannot quietly stop exercising the device
threading it was meant to cover.

Nothing in the science changed: `diff -rq` between the new tree and the
uploaded v1-6 tree reports exactly two differing files,
`test_evaluate_v10.py` and the `manifest.json` that records its hash. The
data CRCs are unchanged, so the full-shape rehearsal and every other result
in Section 15 carry over unmodified.

The lesson belongs with the other two instrument classes in this section. A
broken instrument cannot register a signal; a stale tree runs the wrong
code; and a *host-dependent certification test* is an instrument that was
never itself certified — it reports on the machine it runs on rather than
on the machine that matters. Standing rule: any bundle test that builds a
model and calls an entry point whose `device` defaults to `None` must pin
the device explicitly, because the default resolves differently on the
development host and the target host.
