## What Version 5.5 changes and why

Version 5.4 failed exactly two preregistered controls (see
`reports/hlwm-v5.4-kaggle-results-2026-08-19.md`):

1. Generated-emission calibration rejected only 0.583 of negatives (gate 0.70)
   with a degenerate operating point (commitment threshold 0). The candidate
   policy heads had never been trained on the model's own emissions.
2. Routing collapsed: seed 17 sent 98.4% of audited decisions through one
   expert; seed 29 materially used two.

Version 5.5 responses, all implemented in `experiments/kaggle_hlwm/`:

- **On-policy policy-head phase** (`train_kaggle.py`,
  `collect_on_policy_policy_examples` + `train_policy_heads_on_policy`).
  96 train-anchor emissions are generated by the frozen decision path, graded
  by the deterministic semantic graders, and only the three candidate-level
  heads are fitted on: valid emissions (positives), invalid emissions, the
  anchor's fluent wrong-value answer (semantic negative), and a mechanically
  corrupted snapshot. BCE plus margin ranking, AdamW on the head only,
  before/after separation reported in `policy-head-training.json`.
  Thresholds are then fitted, unchanged, on 64 generated **validation**
  emissions; the test split is never consulted.
- **Router marginal-entropy regularizer** (`modeling_hlwm.py`,
  `_router_marginal_entropy_loss`, weight 0.02): KL of the mean routing
  probabilities to uniform, applied in both local and joint phases alongside
  the existing Switch-style balance term.
- **Preregistered routing audit** (`evaluate_checkpoint.py`): normalized route
  entropy, second-route load, and a causal intervention that pins every route
  window to the least-used expert (`route_override`) and re-scores the
  identical frozen candidate.
- **BF16 autocast** on supporting devices (GradScaler disabled, no skipped
  updates possible); FP16 + scaler remains the T4 path.
- **Memory regime for a 5 GB partition**: token budgets reduced to context
  160 / canvas 96 / brief 96 / causal 320; the real-Qwen preflight now also
  runs a joint-stage forward/backward and fails if reserved memory exceeds
  92% of the device; `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`.
  If the preflight trips on the target slice, the declared fallback is canvas
  80 and causal 256 before any other change.

## Session plan (3 h 30 min wall clock)

| Segment | Budget |
|---|---|
| pip install, bundle checks, unit tests, model download | ~15 min |
| preflight (numerical + memory ceiling) | ~5 min |
| training, seed 29: 128 overfit + 768 local + 1,664 joint = 2,560 microsteps | capped at 2 h 18 min |
| on-policy head phase (96 emissions) + validation calibration (64 emissions) | ~25 min |
| fresh-process 48-output audit with routing interventions | ~20 min |
| packaging: deliverable ZIP, resumable checkpoint, split parts | ~5 min |

**Expectation setting:** a 1g.5gb slice has roughly 0.5–0.7× T4 throughput on
this batch-size-1 workload. The 2,560-step plan may not finish inside one
window; that is handled, not hidden. The 2.3-hour cap checkpoints exact
optimizer/RNG state, the session still runs the head phase, calibration,
audit, and packaging, and the notebook reports `run_complete=false` with the
`training_complete` gate failed. A second 3.5-hour window resumes via
`HLWM_RESUME` (or an attached `hlwm-v5.5-resumable.pt`) with identical example
order and no repeated steps. No gate claim is valid from a truncated run.

## Preregistered capability gate (evaluated once, on the untouched test split)

All Version 5.4 sub-gates unchanged (leakage 0, quality ≥ 0.75, semantic
≥ 0.75, safe abstention ≥ 0.75, committed abstention ≥ 0.70, commit accuracy
≥ 0.70, margins > 0, lane cosine < 0.90, candidate F1 ≥ 0.8× base), plus:

- validation calibration: positive accept ≥ 0.70 **and** negative reject
  ≥ 0.70 **and** balanced accuracy ≥ 0.70, fitted only after the on-policy
  head phase (`policy_heads_trained_on_policy` must be true);
- routing: second-route load ≥ 0.10; normalized route entropy ≥ 0.25;
  least-used-expert intervention moves mean |commit probability| by ≥ 0.01
  (routing must be causally live);
- `training_complete`: the full 2,560 planned microsteps finished with zero
  skipped optimizer updates.

A passing gate authorizes the next research-scale run. It is not a
production-readiness or Qwen-superiority claim; those still require
independently adjudicated correction/abstention data, external benchmarks,
red-teaming, multi-seed replication, and serving tests.
